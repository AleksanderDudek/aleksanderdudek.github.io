MEGAVIDEOPUBLISHER

Privacy Policy

Last updated 4 September 2026

Summary

MegaVideoPublisher is self-hosted software. It runs on the operator's own computer and stores everything in a database on that computer. The authors operate no server and receive no data from any installation. There is no account to create, no telemetry and no analytics.

Who this covers

The "operator" is the person who installed and runs MegaVideoPublisher. Each installation serves exactly one operator and handles only that operator's own material and their own connected accounts.

What is stored, and where

All of it stays on the operator's machine:

  • Videos and generated clips — files on local disk.
  • Transcripts, and the titles and descriptions generated from them.
  • Google OAuth tokens for a connected YouTube channel: an access token and a refresh token, held in the local database so clips can be uploaded later without asking for permission again.
  • The connected channel's id and name, so the operator can see which channel an upload will go to.
  • A posting schedule the operator configures.

Google user data

MegaVideoPublisher's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Specifically, Google user data obtained through the YouTube Data API is:

  • used only to upload the operator's own clips to the channel that operator connected, and to display that channel's name back to them so they can confirm they connected the right one;
  • stored only on the operator's own machine;
  • never transferred to anyone — not to the authors, not to advertisers, not to any other third party;
  • never used for advertising, profiling, or to train any model;
  • never read by a human other than the operator themselves.

The scopes requested are youtube.upload to upload the operator's clips, youtube.readonly to read back the connected channel's name and public metadata for channels the operator has chosen to follow, and youtube to manage the operator's own uploads. No scope is requested that the software does not use.

Third-party services

An installation talks directly to the services its operator has configured with their own credentials — for example a transcription provider or a language-model provider — and to the platforms the operator publishes to. It sends those services only what is needed for the task the operator asked for, and it sends nothing to the authors of the software.

Revoking access and deleting data

The operator can disconnect an account inside the application, which deletes the stored tokens, and can revoke access at any time at myaccount.google.com/permissions. Deleting the installation, or its database, removes everything the software holds — there is no copy anywhere else to request the deletion of.

Security

Tokens are stored in the operator's own database and are never returned by the application's own API — a connection can be inspected only to the extent of whether it works, never for what it holds. Because the software runs on the operator's hardware, the security of that machine is the operator's responsibility.

Children

This is a developer tool and is not directed at children.
